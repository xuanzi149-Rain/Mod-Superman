# 部分5：本地交付与验收

更新日期：2026-10-15。状态：本地核心实现和程序验收完成；玩家独立使用、新包游戏验收及公开部署未完成，部分 5 整体尚未结束。

## 当前可用流程

选择装备 → 描述期望或手动填参数 → AI 解析与必要澄清 → 校验、预览并调整 → 确认并生成 → 后台打包及检查 → 下载 ZIP → 按固定说明安装、检查、停用 → 返回反馈。

采用用户确认的红黑黄 MVP V1 三页界面。真实页面使用 `web/live.js`；旧 `prototype.js`、`model.js` 和设计快照保留为历史原型，不作为当前解析规则。当前网站仅开放装备，不开放治愈真言和历史属性/被动扩展。

当前供应商为阿里云百炼 Token Plan 北京端点、qwen3.7-plus，已通过一次真实模型至下载、反馈的自动验收。此前 DeepSeek 超时及 503 属于历史故障，不代表当前百炼仍被阻塞。

## 装备范围与识别

原始目录 1,872 条模板候选、1,113 条独立 Stats 保留。前端通过 `player_available_only=true` 仅显示 5 件有获取依据的装备：第一滴血短剑、生离死别、死亡追踪者斗篷、白银护符和白银坠饰。

选择器展示类型、固有效果摘要、获取位置与可改字段。白银坠饰仅开放神导术版本；两个普通模板获取方式未核实，先隐藏，不能断言绝对不可获取。白银护符明确标注普通首饰、无固有魔法效果；斗篷标注邪念起源条件。

依据在 `data/equipment_presentation.json`，需确切 UUID 与 Stats 匹配；不是通过模板前缀推断。可获取与修改包游戏验证分开记录。原始 API 默认仍提供全目录候选，便于开发排查。详见[装备选择与获取依据](装备选择与获取依据.md)。

## 实现逻辑与异常恢复

装备原值、字段能力和校验以服务端目录为准。模型仅提议结构化操作，程序处理相对计算并验证；用户确认后才生成。参数变更清除旧预览与确认。未支持要求若被手动舍弃，需要明确接受仅继续支持参数。

单次执行一个打包任务，最多两个等待；同一方案重复提交返回已有状态。打包期间不持有全局状态锁。服务重启把未完成任务标为 interrupted，不自动重跑，需新预览与确认。

浏览器保留输入、会话/制作编号及未保存编辑。结果不明时重发同一模型请求编号，避免“再减半”重复计算；刷新查询服务端状态。下载失败重试已有产物，不重新调用模型或打包。清除 Cookie、过期或更换浏览器不能仅凭编号取回记录。

模型连接等待 10 秒、读取等待 60 秒，调用方总等待 65 秒。超时不自动重试，底层未完成请求仍占并发容量，最多两次模型请求并发。阶段诊断记录耗时、HTTP 状态和字节数量，不记录密钥、请求头或完整原始模型正文；会话历史仍保存正常业务输入与结构化结果。

## 本地运行与数据

入口：http://127.0.0.1:8016/ 。仅监听本机；真实网页必须通过 HTTP 打开，不能双击 HTML 使用完整接口。

启动：`powershell -ExecutionPolicy Bypass -File scripts/run_backend.ps1 -Port 8016`。可用 `-Python` 指定运行时；普通环境先安装 requirements.txt。本机沿用已有项目运行时与依赖，不宣称任意新电脑均已验证。

默认数据目录 `build/backend/mvp-local`，可通过 MOD_DATA_DIR 指定。当前数据存放本机；未来上线后放服务器持久化目录。

| 数据 | 存储与职责 |
|---|---|
| 会话、草稿、请求去重、制作方案 | records.sqlite3 的 records 表，payload 为完整 JSON |
| 浏览器访问归属 | owners 表，保存 token 摘要 |
| 阶段、失败与诊断事件 | events 表，可关联 session_id/plan_id |
| 成功/问题反馈 | feedback 表，关联 plan_id |
| JSON 快照 | 兼容与诊断；仅数据库无相应记录时导入 |
| ZIP、PAK 和检查结果 | 数据目录中对应产物文件 |

SQLite 是正常读取依据，不是仅用于后续分析的附属日志。恢复时需同时保留数据库与 owners 归属。服务启动及每日维护进行 SQLite 在线备份，清理生成后超过 7 天的关联交付产物，不删除制作和反馈记录；无 generated_at 的旧产物不自动清理。同盘备份不等于异机灾备，长期记录保留策略仍待制定。

记录访问统一检查匿名浏览器 HttpOnly、SameSite=Lax Cookie；公开模式额外 Secure。跨来源 POST 拒绝，请求体上限 24KB，按 IP 每分钟最多 10 次模型请求与 60 次写请求。

## 产物、说明和反馈

ZIP 含 PAK、修改清单.json、使用说明.txt。PAK 已由程序打包，用户只需解压、安装启用和验证，不需要再次本地打包。

固定中文说明填入制作编号、参数、PAK 名称、游戏版本依据、共用记录范围和安装/停用步骤；网页读取 ZIP 中同一文本。历史目录环境 v4.1.1.7631656 来自用户截图，不代表新包游戏通过。

问题反馈阶段为生成、打包、下载、安装或游戏效果，问题描述必填；反馈入库记为 user_report，不改写 game_validation。成功下载或脚本反馈不能推断玩家已安装或生效。

主要新增接口：POST /api/plans/{id}/tasks、POST /api/plans/{id}/feedback、GET /api/plans/{id}/instructions、GET /health。正式页面使用 tasks；旧同步 generate 仅本地兼容，MOD_PUBLIC=1 时禁用；公开模式关闭 /lab。

## Render 准备与暂缓部署

Dockerfile 使用 Python 3.12、.NET 8 和固定版本 LSLib v1.20.4，校验发行包摘要；包含原始目录与获取元数据，不复制密钥或历史构建数据。镜像构建要求固定模型响应配合真实 Linux 打包/解包检查。
