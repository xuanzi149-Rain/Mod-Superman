# 部分 4：实现与学习记录

## 固定规则与学习方式

本部分使用固定工作流：目录选择 → 模型理解 → 程序计算与校验 → 必要澄清 → 预览 → 人工确认 → 已有生成下载。模型不具有生成权限，不能输出内部对象标识、文件路径或代码。学习目标是理解上下文、结构化输出、工具职责、状态管理和人工确认，不增加自主 Agent、RAG 或多智能体。

已确认规则：明确值直接赋值；重量相对操作由 Decimal 计算；“再减半”使用草稿，“原重量的一半”使用原值；撤销仅删除指定草稿字段；模糊或矛盾需求追问；混合请求保留可支持草稿，独立选择仅继续支持部分。重量范围和精度复用目录规则，不自动取整。所有生成都需独立确认。

预先固定 data/ai_cases.json 的 24 个案例，开发集16条，保留集8条。保留集不用于调 Prompt 后反复调参。结果由实际测试填写，不事先承诺通过率。

用户已确定工作流、计算基准和本地演示页。智能体负责实现、检查和记录；用户亲手体验及游戏内验证尚未开展。

## 讲解 1：工作流与 Agent

输入是用户需求，模型输出修改操作，程序执行计算和校验，人确认之后程序生成。自主 Agent 通常由模型决定后续行动；本项目由程序规定流程。这样能明确定位错误来自理解、规则还是执行。

## 讲解 2：Prompt 与结构化输出

prompts/equipment-v1.md 规定模型的任务、允许操作和歧义处理。backend/ai_protocol.py 用 Pydantic 定义输出合同。JSON 合法只代表能被读取；字段是否合法、操作是否允许仍需结构和业务校验。例如 name 字段的 multiply 操作必须被拒绝。

## 讲解 3：状态与工具职责

草稿是当前有效修改，聊天记录是交流历史；二者分开保存。增量操作只作用一次，请求编号防止重复执行。“重量减半 → 再减半”是连续两次乘0.5；“改为原值一半”重新选择原值计算。Decimal 保证十进制计算规则明确；超过三位小数时要求用户选择目标，不替用户取整。

## 讲解 4：模型 API

服务端读取密钥，通过 HTTPS 发出一次有60秒超时的请求；输入只有当前对象与必要对话，不发送整份目录。模型返回操作后才能经过程序校验。请求失败不代表用户要求不支持，必须单独记录。用量未知时记 null，模拟结果与真实 API 证据分开。

## 讲解 5：人工确认

预览是用户能够核对的固定方案，生成接口读取该方案而不接受临时夹带参数。AI 草稿更新后原预览失效，生成端检查会话版本。用户在聊天里说“确认”也不能替代独立按钮。安装步骤、影响范围与游戏验证状态来自程序。

## 讲解 6：评测与问题归因

每条案例先定义预期，再调用模型。评测核对完整草稿，而非只检查包含某个正确字段，防止额外修改漏检。对于模糊需求，正确追问才算通过；对于非法重量，程序明确拒绝才算通过。开发集可用于定位问题，保留集只做最终检查。本轮没有根据保留集结果调整 Prompt。

## 接口与运行

本机启动：`powershell -ExecutionPolicy Bypass -File scripts/run_backend.ps1 -Port 8014`，浏览器访问 `http://127.0.0.1:8014/`，接口文档为同地址 `/docs`。默认脚本端口仍为8000；本轮8000已有其他服务，所以验收使用8014。演示服务只绑定127.0.0.1、单进程，不提供公开访问。

服务端优先读取环境变量，其次读取 `.env.local`；`DEEPSEEK_API_KEY` 为密钥，`DEEPSEEK_MODEL` 为模型。示例文件 `.env.example` 不保存密钥。每次模型请求重新读取配置，填写本地配置后无需重启；日志不记录密钥或鉴权请求头。

| 接口 | 请求字段 | 返回 |
|---|---|---|
| POST /api/ai/sessions | object | 新会话，version=0 |
| GET /api/ai/sessions/{id} | 无 | 草稿、原值和规则、历史、问题、预览 |
| POST /api/ai/sessions/{id}/messages | version、request_id、text | 校验后的草稿与解释；失败保留旧草稿 |
| POST /api/ai/sessions/{id}/draft | version、request_id、changes、accept_supported_only | 完整替换草稿；清除此前问题 |
| POST /api/ai/sessions/{id}/preview | version、request_id | 会话内的固定预览 |

version 是读取会话获得的当前版本；request_id 是本次操作唯一编号，同一请求重发保持编号，主动重试失败请求使用新编号。messages 文本上限4000字符。手动 changes 为空对象代表撤销全部修改；其余参数复用现有规则。混合请求须勾选“仅继续已支持部分”再保存参数，不能只在聊天中说确认来跳过。

最终仍用 `POST /api/plans/{plan_id}/generate`，传入 `confirmed` 和 `accept_experimental`；这里不接受参数修改。AI 预览额外绑定会话与草稿版本。会话处理请求期间也不能执行旧预览。成功历史包不因草稿后续修改而删除。

会话保存在 `build/backend/ai_sessions`，评测在 `build/backend/ai_evaluations`。程序保存全部历史，每次模型上下文只包含最近六轮以及结构化有效草稿。异常分类包括模型配置、鉴权、限流、超时、响应结构、参数、过期版本和生成失败；没有自动循环重试。手动填写明确完整参数可结束澄清。

检查命令（先设置 PYTHONPATH 为项目 `.runtime/python`，使用部分3记录中的 Python 运行时）：

```powershell
python -m unittest discover -s tests -v
python -m scripts.evaluate_ai --split development
python -m scripts.evaluate_ai --split holdout
python -m scripts.verify_ai_flow
python -m scripts.verify_ai_flow --real
```

`evaluate_ai` 和 `verify_ai_flow --real` 会实际调用模型并产生用量；不带 `--real` 的链路验收使用明确标注的固定模型响应。单元测试不会调用付费 API。固定案例仅覆盖第一滴血短剑的代表性说法，五字段的程序测试另使用具备双手伤害能力的目录对象，不把24条案例理解成全目录模型验证。

## 失败案例、修复与限制

1. 初始模型配置为空：返回 model_not_configured，保留输入；用户填写后发现值位于示例文件，已移到被Git忽略的本地配置，清空示例值后真实调用成功。这是配置问题，不统计为模型理解错误。两次早期中断记录仍保留，不冒充完整评测。
2. Windows沙箱拒绝测试临时目录与本地socket：改在获准的正常本机环境运行，最终回归通过。这是验收环境问题。
3. 页面失败恢复检查发现手动校验错误会重新渲染旧表格：已保留未保存值，并阻断预览/生成；重量等常见错误转换为中文。新增HTTP断言验证中文提示。
4. 保留了既有 TestClient 的依赖弃用提示；未为本轮增加无关依赖，测试可通过。后续依赖维护时再处理兼容性迁移。
5. 24条固定案例不是全量语言覆盖。真实模糊需求演示有一次同时提出两个相关问题，仍可完成任务，但可在后续用户测试中评价是否需要减少提问数量。
6. 新包尚未游戏验证，未公开部署；没有账户、跨进程协调或自动产物清理。保持单进程本地演示，正式网站交付与用户反馈留到部分5，长期评测与迭代留到部分6。
