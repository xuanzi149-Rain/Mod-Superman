# 玩家无需资源 ID：C 阶段试用修复

日期：2026-10-17。用户反馈：编辑轻语匕首的沉睡效果时，网站要求填写状态系统 ID，甚至给出未核实的示例标识。

## 原因

原 task8-v6 已有“不索要技术标识”文字，但候选主要靠少量别名和英文标识检索，没有完整使用本地中文名称。模型输出问题也缺乏语言边界兜底，最终把资源查找责任交给玩家。仅增加一句 Prompt 禁令不足以解决此问题。

## 当前规则与实现

1. `prompts/player-language.md` 为全项目共享规则，由 1.0 解析和 1.1 解析/文案核对的提示构建器统一注入。当前任务 8 版本为 task8-v7；历史版本文件保留证据，不伪造过去运行结果。内部 JSON 字段继续使用真实资源标识，玩家不需要输入这些标识。
2. 从已提取中文本地化数据取得名称、原生说明；先找名称/别名，再在原有一次补查中加入近似名称候选。最多 40 个原生候选，优先保留当前装备和已选资源。近似命中仅作为候选，不直接改变方案。
3. 向模型补充装备原生字段及武器命中效果的真实引用。轻语匕首的原生 WeaponFunctors 引用沉默状态；“沉睡”检索得到多个真实状态。两者不能静默混同；必要时按新增/修改目标或实际行为澄清。原生字段能被读到不代表已支持任意修改。
4. 多个候选用名称和可核实的效果差异询问；不让玩家辨认内部变体。没有候选则保留需求，请玩家描述触发、对象、效果和数值，或主动选择替代方案；系统不能自动降级、删除或承诺等价。
5. 模型若仍在问题、说明或选项中索要 ID，程序将该问题转成待补查信息，保留要求关联，最多补查一次。仍未解决则提供玩家可理解的说明，保持生成阻塞；不无限重试、不伪造引用。文案核对解释与旧版 AI 输出也加入语言保护。
6. 恢复历史草稿时改写此类旧问题，保留问题身份和需求关联，不撤回或假装完成原需求。

## 检查与边界

测试覆盖：轻语匕首的沉默原生引用与沉睡候选同时进入上下文；中文错字/别名检索；短词“沉默/沉睡”不做模糊等同；模型连续两次索要 ID 仍不能向玩家显示该问题；原需求保留且不自动生成替代效果；历史问题恢复、正常持续时间问题、审核解释和 1.0 输出保护。

初测发现近似检索只检查本地化标准名称，未检查已知别名（“治愈光辉/治疗光辉”），已补齐别名参与检索并回归。测试日志为 `build/v1.1/player-language-final.log`。

本轮没有新增真实模型调用，因此本地固定输出测试只证明程序约束与流程，不能声称真实模型已在这条需求上解析成功；也没有确认用户具体想新增还是修改、沉睡持续时间及触发等设计。未扩展沉睡机制的编译支持，未开展 D、游戏实测或公开部署。

最终结果：合并回归 59/59 通过（100.366 秒）；随后对候选内部名称直接出现在选项中、未写“ID”字样的情况补强保护，7/7 针对性复核通过（8.920 秒），与前批用例重叠，不相加为独立样本。对应日志为 `player-language-final.log` 与 `player-language-guard.log`。原本地网站已重启，只读接口确认 Prompt 为 task8-v7，中文“沉睡”状态检索返回 12 条候选（不是 12 条已审核可生成效果）。
