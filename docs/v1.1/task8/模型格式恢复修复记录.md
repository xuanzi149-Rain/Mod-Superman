# 模型格式错误恢复修复

2026-10-17，属于 C 阶段试用维护，D 未开展。

## 问题与原因

用户看到“模型返回的结果格式不符合要求”。本地错误记录显示，模型输出了 relative_parameter / damage / add / 1。该操作仅支持重量、护甲、附魔和价格；伤害字段为骰子格式，不允许普通数字运算。严格校验正确拦截，但此前直接把模型协议错误交给玩家重试。

未从错误日志推断玩家完整原话，也未修改其现有草稿。

## 修复

- task8-v9 明确相对操作允许字段。不能把伤害增加 1 偷换成骰子数量或附魔增加 1；必要时询问固定伤害与骰子变化的差别。
- Task8Model 在结果进入草稿应用之前校验。协议、JSON、空响应和截断问题最多自动纠正一次，沿用同一原始上下文、修订号和完整协议。纠正诊断作为数据处理，不能成为新增用户指令。
- 上下文过期、网络、鉴权和限额等错误不进入此重试路径。仍执行原有严格校验，不放宽可执行字段。
- 两次解析均不合格：不采用其中任何部分修改；按原文保存全部需求为一个阻断待处理项。长输入按协议长度分段保存。明确这是自动解析失败，不代表功能不支持，不索要技术标识。
- 文案核对连续失败：保留原文和参数，不标记核对通过，返回具体原因。
- 日志记录各次用量、失败原因及恢复状态，并汇总返回的 token 数。额外纠正最多增加一次模型调用的成本与等待时间；缺失用量不估算。
