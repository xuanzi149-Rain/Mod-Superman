## 3. 发现与修复

| 问题 | 证据与判断 | 修复及验证方向 |
|---|---|---|
| 沿用原版技能距离时，相对计算拒绝 | 当前覆盖为 null，但原生明确有距离 | 使用经资源提供的有效原值作为 current 基准；仍拒绝缺失原值和非数值 |
| 审核结果采用前未检查资源变化 | 冲突建议等待采用期间资源改变，旧建议仍能采用 | 解析、核对及采用分别检查资源指纹和修订；过期结果拒绝 |
| 同一文案字段冲突请求后写覆盖前写 | 两个名字指向同一字段未被拒绝 | 在应用前拒绝重复目标字段，保留原草稿 |
| 切换对象 reset 会保留旧待审文案 | 旧 equipment 文案可能落到新对象 | 清空旧待审绑定，把未撤回的文案要求转成重新定位阻断 |
| 独立组成功仍无法解除对应问题 | 另一无关组失败导致所有 issue_update 被阻止 | 按该问题关联的操作/文本是否成功判定，不被无关失败牵连；reset 文案也计为已处理 |
| 文案事实缺少原生继承依赖 | 原装备字段只列引用，未展开最终依据 | 展开保留的原生依赖；缺少可靠依据明确标记。只要求本段文字实际依赖的事实完整，避免无关缺口阻断独立词条 |
| 即时治疗 duration_turns=null 被拒绝 | 模型表达“无持续时间”，没有提出持续治疗 | 明确缺省与 null 对即时动作等价；状态动作仍须有效回合；保留 B 技术占位及规范化记录 |
| 能力缺口未提供检查证据 | 混合需求的价值修改连同无证据 capability_gap 一起被协议拒绝 | 上下文提供真实支持事件及永久成长规则缺失证据；Prompt 明确引用本次实际证据，合法组和缺口分别保留 |
| 状态文案漏写刷新规则，装备效果漏写生效条件 | 结构检查通过不等于语义通过 | 提供明确 activation_condition、stacking_explanation、关联状态叠加事实；逐条阅读修订后文案 |
| 零属性兼容占位被误读成调整值归零 | 纯护甲状态实际没有力量效果，但原生输出出现 Ability(Strength,0) | 适配合同仍保留 0，固定生成器不输出无效属性项；测试确认生成物无这项伪语义 |
| 核对器误判普通名称、编造名称/目标限制 | “独立状态”被审美式判冲突；文案使用未提供中文技能名或盟友限制 | 提供实际 display_name，明确不审美拒绝普通名称、不翻译内部 ID 猜名、不加无证据的对象限制；无原文只能返回 not_provided |
| 新变体 F06 不必要追问 | effects 为空被误解为装备没有原被动，重复询问已指定的“平衡” | 候选明确 inherited_original/removed_original，Prompt 说明新增效果与原生继承的区别；原始首测 7/8，F06 转回归 |
| v5 补充措辞产生操作类型混淆 | 解析输出把 passive_copy 效果类型写成操作 kind | v6 明确 add_effect 是操作、payload.effect.kind=passive_copy 是效果；保留 v5 失败，v6 F06 回归通过 |
| 验收工装两处误报 | M02 原有敏捷规则已满足；C09 功能解析通过但测试草稿尚未选择获取入口 | 按最终有效值检查；未完成获取的草稿不冒充可编译。原始记录保留，区分模型问题与工装问题 |
