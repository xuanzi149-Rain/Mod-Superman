## 1. 输入如何成为可确认方案

有效草稿、原始数据和需求账本 → 按本轮表达组织候选资源与最近三轮上下文 → 模型返回声明式解析 → Schema 与语义检查 → 程序按依赖组尝试修改 → 保留合法组与未解决要求 → B 固定编译器提取实际效果事实 → 独立模型任务核对文案 → 绑定方案和资源的审核凭据 → 展示修订号、摘要及修改前后数据 → 确认后交给 B 生成。

模型只提出操作和文本。程序决定数字运算、对象 ID、组是否可保存、校验是否通过、确认是否有效以及如何生成文件。审核失败、未解决需求、过期上下文或过期确认均不能通过任务 8 确认入口。

## 3. 使用入口和异常边界

任务 9 将来可调用 `Task8Session(plan, catalog, resources, inheritance=...)`，随后依次使用 `submit(text, request_id)`、需要时 `review_text()`、`preview()`、`confirm(expected_revision, expected_digest)`，最后交给 `generate_draft(session.draft, ...)`。当前入口用于 Python 集成检查，网站尚未接入。

- `submit` 返回 revision、applied、failed、before、after 和 unresolved，供后续网站明确展示每次修改结果。
- 内部资料缺失最多补查一次再解析，不作无界自动重试。格式/协议错误返回失败并保留已有草稿。
- 精确文案冲突保留待处理；只有明确选择替换，才使用审核建议。主动润色的合格候选可进入方案预览。多条待核对文案统一采用，避免凭据跨版本。
- `use_standard_text()` 是显式恢复操作，放弃相关自定义文本，但不清除其他未解决需求。
- 六类效果与十个基础字段仍由 B 校验具体对象和依赖；存在类别映射不代表所有对象组合都合法。重新设计继承内容须逐项明确，不能自动清空原装备。
- 自然语言重量由模型按协议输出 kg，程序检查数值和精度；当前未实现独立的自由文本单位解析器。已同步规格表述，不能把模型转换称为确定性单位识别。
- 候选目录为当前引用、少量已知中文别名及资源名称匹配，不是完整中文检索系统。找不到时保留缺口；未知能力不靠猜测补齐。
- 会话、快照及凭据在内存中，进程重启后不恢复。持久化、HTTP 错误展示及网页交互留待任务 9/10。
