# 新装备统一营地个人宝箱获取（2026-10-19）

## 用户决定与实现

取消第一章达蒙商店入口。新装备固定使用 camp_chest，不询问章节或获取地点；修改已有装备保持原获取方式。新建时自动设置，旧 dammon_act1 草稿迁移并重新确认。旧已下载 PAK 不会被修改，需要重新生成。

固定生成器输出 Public/<module>/OneTimeRewards/OneTimeRewards.lsx：Amount=1，ItemTemplateId 指向本次独立 RootTemplate，UUID 由 module UUID 和固定用途键确定。不写 TreasureTable、不覆盖个人宝箱模板或公共商人库存，不添加 Script Extender/Lua/Osiris 脚本。奖励文件没有章节、商人存活或区域判断。相同模块重复生成保持奖励标识，避免以新标识重复发奖；新的独立模块有独立奖励标识。

设计行为：启用 Mod、加载存档后返回营地，在个人宝箱领取一次。不是每次读档或物品卖掉后都补发。实际到账需要游戏加载奖励，不能解释为勾选 Mod 的瞬间即修改存档。

## 依据

参考作者的 [OneTimeRewards 实作记录](https://github.com/etonai/BG3Mods/blob/main/docs/instructions/BG3_Modding_Lessons_Learned.md#onetimerewards-travelers-chest)中营地个人宝箱投放的路径、XML 字段及一次性 UUID 规则。其章节标题实际为 OneTimeRewards (Traveler's Chest)，若锚点不可用可在页面搜索 OneTimeRewards。

本地基础游戏提取未找到同名奖励配置，因此不能声称此格式直接来自本地原生样例。LSLib 转换与反向转换确认字段可解析；其二进制往返将 region 名规范化为 root，检查仅在往返产物中兼容此转换，最终包仍保留原始 OneTimeRewards LSX 路径与 region。

- 53 项本地 Python 测试通过：营地奖励标识稳定、不同模块隔离、数量/模板引用篡改被拒绝、旧达蒙迁移、修改已有装备不加奖励，以及编译器/Task8/佩戴者附伤回归。
- 1 项 HTTP 模式/目录测试通过；旧达蒙创建参数返回 camp_chest，基础模板限制保持。
- 前端语法及修改结果列表检查通过。获取下拉框移除，确认页显示固定营地个人宝箱入口。
- 戒指与长剑各生成一个 PAK，通过奖励文件转换/反向转换、打包及解包字节比对。证据：build/camp-chest-acceptance/*/*/attempt-*/result.json。首次尝试因转换后 region 名变化被检查器拒绝，修正仅用于往返文件的检查后，两包通过。
- 未运行游戏。第一、二、三章旧存档的到账、多人个人宝箱归属、卸载再启用的行为尚未实测，不能宣称已验证“任何存档一启用必定到账”。实现不设章节条件，与游戏实测保证区分。
