# 1.1 方案协议（第一轮）

实现：`backend/crafting_v11.py`。版本 `1.1-draft-4`；JSON Schema：`data/v1.1/plan.schema.json`。这是独立模块，尚未接入 HTTP、SQLite 或 AI Prompt。旧版 draft-1/draft-2/draft-3 不自动兼容，调用者应重新按 Schema 提交。

输入分为用户目标、基础装备目录引用、展示文字、基础参数和带稳定草稿 ID 的效果。模式为 modify_existing / create_new。输出文件路径、游戏新 UUID、Stats 名和文本句柄不属于模型输入，由后续生成器分配。所有模型拒绝未知字段，数值不接受 NaN/Infinity。

当前效果类型包括 constant（六属性）、bonus（先攻/移动/技能/豁免/AC/抗性）、trigger（武器命中、治疗、受伤事件后的合法伤害/治疗/状态组合）、independent_status、grant_spell 和 passive_copy。基础参数增加武器特性与敏捷护甲规则，资源增加 appearance_equipment/icon。当前可执行规则由 scripts/crafting_compiler_v11.py 检查，详见阶段 B 记录；未审阅的对象和组合仍拒绝，user_goal/unresolved 保留原意。Schema 的枚举与数值范围属于产品边界，不是游戏极限。

| 操作 | 含义 |
|---|---|
| edit_effect add/update/delete | 用稳定草稿 ID 增、改、删本次效果；删除不会移除原版被动 |
| removed_original_passives | 单独表达移除原装备效果的意图；编译完整有效被动列表，审核已知 Honour 双路径 |
| restore_parameter | 删除覆盖值，恢复继承；不猜测原值 |
| replace | AI 与手工共用入口，检查旧修订号，记录来源和摘要，修订号增加并撤销确认 |
| review | 提供资源目录时走 B 编译器规则；未提供时保留旧版基础字段门槛 |
| confirm | 只接受 ready 状态，必须匹配修订号和预览摘要 |
| begin_generation | 再检查确认与能力；这里只实现状态门槛，不执行生成 |

| 当前状态 | 条件/操作 | 下一状态 |
|---|---|---|
| draft / failed / confirmed | review，有问题待回答 | needs_clarification |
| draft / failed / confirmed | review，能力缺失 | unsupported |
| draft / failed / confirmed | review，无问题 | ready |
| ready | 用户确认匹配修订号和摘要 | confirmed |
| confirmed | 再次能力检查通过 | generating |
| generating | 成功 / 分类失败原因 | succeeded / failed |
| 非 generating | replace | draft，旧确认失效 |

返回 plan 是深拷贝，外部修改不会悄悄改变已确认内容；运行中的任务拒绝编辑。失败重试需重新 review 和 confirm。历史保存来源及完整方案快照；目录变化会在生成门槛使旧确认失效。独立状态通过 status_draft_id 关联，不能与 status_ref 同时使用；孤立、错类型或持续回合不一致会被拒绝。法术位使用 level/amount 严格结构。原生引用另经资源目录检查，检查合法仍不等于生成器已实现。生产接入时还需把状态、历史与任务结果持久化，处理并发事务及进程恢复，属于阶段 C。

请求示例见 `data/v1.1/plan-examples.json`。在资源目录可用且来源未变时，普通长剑新建示例可通过 B 规则；必须确认之后才打包。命令行调用见阶段 B 执行记录。

## draft-4 补充规则

新防具必须通过 25 个原生 EquipmentRace 配置及其父级回退链的模型检查。特殊模板使用 template_behavior=preserve_reviewed 显式确认已审阅的动作和标签；默认拒绝，未知动作仍阻止生成。

独立状态支持 replace/ignore/additive 及结构化 bonuses。grant_spell 的 status_duration_turns 作用于可解析的施加状态动作。技能复制包含执行依赖、升环、多选容器和 AI 分支，保留延迟效果；免疫与条件查询不擅自复制其目标。未知函数、缺失引用、循环及递归触发风险明确报错。全部资源审核输入参与确认摘要，数据变化需重新确认。
