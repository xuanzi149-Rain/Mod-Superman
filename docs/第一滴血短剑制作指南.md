# 第一滴血短剑基础伤害修改指南

本指南保留首次手工制作过程。2026-10-13 已发现完整普通版记录会覆盖荣誉规则满血附伤，后续改用 v2 仅写 Damage 的方案；不要再次发布旧项目覆盖修复包。当前步骤见《第一滴血短剑荣誉附伤修复.md》。

将原装备的基础伤害翻倍，先手工制作并验证，再用 Python 复现。若本地原值为 `1d6`，目标为 `2d6`；专属满血附伤、角色属性加值和其他效果保持原规则。这里的翻倍指基础伤害骰数量翻倍，不保证每次攻击的最终随机伤害恰好翻倍。

当前进度：手工包的物品与战斗日志截图显示基础骰 2d6，用户报告伤害符合预期。Python 已复现两份文件，自动检查通过；程序包的打包和游戏复验待完成。实际游戏版本、满血附伤触发、普通短剑及停用恢复仍待核对。逐项证据填写到同目录的《第一滴血短剑验证记录.md》，程序操作见《第一滴血短剑Python复现.md》。

## 创建项目并打开 Stats Editor

1. 在 Steam 启动 Baldur’s Gate 3 Toolkit。
2. 如果首次启动要求 Data 路径，在 Steam 右键游戏 → 管理 → 浏览本地文件，选择实际游戏安装目录中的 `Data` 文件夹。
3. Browser 窗口选择 **New Project** 或 **Create +**，项目名填 `FirstBloodDamageTest`，点击 **Create**。
4. 出现关卡选择窗口后，展开 `Act_1A_WLD`，选择 `WLD_Crashsite_D`，等待加载。该关卡只是本次编辑器入门环境，数值修改不需要修改地图。
5. 点击主工具栏的柱状图图标，打开 **Stats Editor**。

预期结果：主窗口显示测试项目与已加载关卡，Stats Editor 左侧显示项目列表。保留包含窗口标题和项目列表的截图，再继续查找装备。界面与说明不符时，记录当前窗口和报错，不猜测按钮位置。

本次不导入模型或纹理，暂不配置用于资源导入的 Source Asset Data Path。[官方项目创建说明](https://docs.baldursgate3.game/index.php?title=Getting_Started:_Creating_a_New_Mod)、[官方 Stats Editor 入口和搜索示例](https://docs.baldursgate3.game/index.php?title=Making_a_Basic_Spell)。

## 核对装备记录与继承关系

1. 在 Stats Editor 的基础游戏项目中展开 Stats，找到 Weapon 表。具体所属项目以本地数据为准，不预设一定属于某个模块。
2. 打开表后按 `Ctrl+F`，搜索 `UND_Duergar_ShortswordOfFirstBlood`；未找到时搜索 `FirstBlood`。这是待核对的候选标识，不能据此直接写入正式支持目录。
3. 记录匹配行的 Name、Parent、装备引用、被动和伤害相关字段。沿 Parent 查看原始基础伤害来源；空白值可能代表继承，不能当作零。
4. 保留目标记录、父记录和关键字段截图，确认实际控制方式。只有此时才能决定具体修改哪一格，以及它接受骰表达式还是其他值。
5. 查看目标行的右键菜单，按当前 Toolkit 支持的覆盖操作，将该记录覆盖到 `FirstBloodDamageTest`。找不到覆盖入口时，提供菜单截图后继续定位，不改公共父记录，也不创建新装备变体。

预期结果：测试项目中可以编辑目标装备，原标识保持一致，基础伤害原值与继承来源清楚。[装备候选标识资料](https://bg3.wiki/wiki/Shortsword_of_First_Blood)仅用于查找，字段与原值以本地记录为准。

## 修改并发布本地包

1. 保存未改变伤害的项目源文件与运行文件副本，记录各自的实际相对路径。
2. 在目标装备覆盖记录上修改已核对的基础伤害。若原值确认为 `1d6`，将有效基础骰改为 `2d6`；保留原伤害类型、被动与其他配置。
3. 保存全部修改，再保留修改后的对应文件和字段截图。比较前后内容，确认未修改普通短剑公共父记录。
4. 打开 **Project → Project Settings**，填写必需的 Name、Description 和 Thumbnail，保存。
5. 点击 **Publish Local**，选择本地 `.pak` 保存位置，记录输出文件与发布日志。该操作无需认证，不上传到 mod.io。[官方本地发布说明](https://docs.baldursgate3.game/index.php?title=Getting_Started:_Publishing_a_Mod)。

编辑器专用数据位于游戏 `Data/Editor/Mods/<实际模块目录>`；运行时 Stats 等内容位于 `Data/Public/<实际模块目录>`。目录名以项目生成结果为准，不假设与显示项目名完全一致。保存最小相关文件，不把整个游戏数据目录放进仓库。[官方目录说明](https://docs.baldursgate3.game/index.php?title=Getting_Started:_Creating_a_New_Mod)。

## 游戏对照测试

1. 保留原存档，创建测试副本，记录难度、角色属性和其他启用 Mod。停用会改变武器或伤害的 Mod。
2. 将发布包放入 `%LOCALAPPDATA%\Larian Studios\Baldur's Gate 3\Mods`，在游戏内 Mod 管理界面启用，重新加载测试副本；必要时卸下再装备短剑。
3. 检查装备说明和战斗日志中的基础伤害骰；对受伤目标使用主手普通攻击，排除满血附伤干扰。
4. 再对满血目标测试专属附伤，确认数值与条件保留。优先选择无穿刺抗性或易伤的目标，避免暴击、偷袭、涂毒和其他附伤，记录无法排除的影响。
5. 检查普通短剑，确认没有被一起修改。
6. 停用测试 Mod，重新加载原测试档，确认恢复原值。

以伤害公式与日志组成为验收依据，不以一次攻击的最终数字或少量攻击均值推断翻倍。截图与用户描述分别保存；用户报告有效不等于智能体亲自观察过游戏。

## Python 复现

进入条件：手工样例在游戏中通过，修改前后文件已保存，控制字段、原值、继承关系和打包路径都已核对。

使用现有 Python 3.11 和标准库。读取已验证模板，精确定位目标记录，按原值计算两倍基础骰，生成文件和修改清单。保留原装备标识，不全局替换 `1d6`；目标缺失、重复或原值不符时停止并说明原因。输出先保存到独立目录，不覆盖基准文件。

将输出接入同一测试项目的实际打包路径；检查编辑器重新打开和保存是否重写输出。如果重写，先解决编辑器源文件与运行文件同步问题，再打包。使用相同游戏测试流程复验，不能把文件检查通过当作游戏验证通过。
